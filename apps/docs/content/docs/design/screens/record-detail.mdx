---
title: その日の記録
description: 過去日の閲覧・編集・新規入力・削除
---

ルート `/records/$date`（`$date` は `YYYY-MM-DD`）。認証必須。特定の日付を対象とする操作をすべて引き受ける。

対応: US-8（記録の編集）、過去日の新規入力、記録の削除

## 位置づけ

「過去日の新規入力」「編集」「削除」はいずれも特定の日付に対する操作であり、扱う UI は同一になる。画面を分けず 1 つに集約する。

[今日](/docs/design/screens/today) は、この画面を当日の日付で開いたものと同じ構造を持つ。`RecordCard` と `TimeOfDayTabs` は両画面で共有する。両者の違いは以下のみ。

| 項目 | 今日（`/`） | その日の記録（`/records/$date`） |
| --- | --- | --- |
| 対象日 | 常に当日 | URL の `$date` |
| 下部タブ | あり | なし（戻る操作で呼び出し元へ） |
| 推移グラフ | あり（直近 7 日） | なし |
| 削除 | なし | あり |

当日の削除が必要な場合は、履歴一覧から当日の行を開く。

## レイアウト

| 順 | 要素 | 内容 |
| --- | --- | --- |
| 1 | ヘッダー | 対象日（`9/3（水）`）と戻る操作 |
| 2 | 朝／夜タブ | `TimeOfDayTabs` |
| 3 | 記録カード | `RecordCard`。今日と同一 |
| 4 | 削除 | 控えめな削除ボタン |

## 朝／夜の初期選択

| 状況 | 初期選択 |
| --- | --- |
| 朝のみ記録済み | 朝 |
| 夜のみ記録済み | 夜 |
| 両方記録済み | 朝 |
| 両方未記録 | 朝 |

当日の記録画面と異なり、時刻による自動判定は行わない。過去日を開く時点で「今が朝か夜か」は無関係なため。

## 差分の起点

[今日](/docs/design/screens/today) と同じ規則に従う。朝は前日夜、夜は同日朝を起点とし、起点が存在しない場合は差分を表示しない。

## 保存

| 状況 | 操作 |
| --- | --- |
| 当該タイミングが未記録 | `POST /api/records`（`date` と `timeOfDay` を明示） |
| 当該タイミングが記録済み | `PATCH /api/records/:id` |

`POST` が `CONFLICT` を返した場合は、その日付・タイミングの記録が既に存在する。記録を読み直して `PATCH` に切り替える。

## 削除

| 項目 | 仕様 |
| --- | --- |
| 配置 | 画面下部。主要操作と視覚的に区別する |
| 対象 | 選択中のタイミング（朝か夜）1 件のみ。日付単位でまとめて消さない |
| 確認 | 確認ダイアログを挟む。取り消しは提供しない |
| 完了後 | 呼び出し元（履歴一覧）に戻る |
| API | `DELETE /api/records/:id` |

朝夜を一括削除しないのは、誤って片方だけ別の日に書いた場合の修正が主な用途であるため。

## エラー

| 条件 | 挙動 |
| --- | --- |
| `NOT_FOUND` | 「記録が見つかりません」を表示し、履歴に戻る導線を出す |
| `FORBIDDEN` | 同上（他ユーザーの記録に到達した場合） |
| `CONFLICT` | 既存記録を読み直し、`PATCH` に切り替える |
| `VALIDATION_ERROR` | 該当バーの直下にメッセージを表示 |
| `$date` が不正 | 履歴にリダイレクトする |
