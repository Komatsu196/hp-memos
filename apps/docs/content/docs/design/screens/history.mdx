ルート `/history`。認証必須。振り返りのための画面で、グラフを上・一覧を下に縦に並べる。

対応: US-6（記録一覧表示）、US-7（推移グラフ）、US-13（グラフの朝夜対応）

## レイアウト

| 順 | 要素 | 内容 |
| --- | --- | --- |
| 1 | 期間セグメント | 7 日 / 14 日 / 30 日 |
| 2 | 推移グラフ | `TrendChart`。選択中の期間 |
| 3 | 記録一覧 | 日付降順のリスト |
| 4 | 下部タブ | 今日 / 履歴 / 設定 |

グラフを最上部に置く。「回復しているか分からない」というコア課題に答えるのはグラフであり、画面を開いた瞬間に目に入る位置に置くことを優先する。

期間セグメントはグラフのみに作用し、一覧の表示範囲には影響しない。一覧は常に全期間を新しい順に辿る。

## 推移グラフ

| 項目 | 仕様 |
| --- | --- |
| 種別 | 折れ線（Recharts） |
| 系列 | 体力・気力の 2 系列。色は全画面共通 |
| X 軸 | 記録点（1 日あたり最大 2 点。朝・夜） |
| Y 軸 | 0〜5 固定。データに応じた自動スケールにはしない |
| デフォルト期間 | 7 日 |
| 期間切替 | 7 日 / 14 日 / 30 日 |
| 欠損日 | 線を切る |
| 凡例 | 体力・気力と、1 日 2 点であることを明示する |

Y 軸を 0〜5 に固定するのは、期間を切り替えても縦の目盛りが変わらず、期間をまたいだ比較が成立するようにするため。

### 欠損日の扱い

未記録日では折れ線を途切れさせ、空白として見せる。前後の点を結ぶと、データのない区間を「なだらかに推移した」かのように見せてしまい、記録がないことと値が低いことが区別できなくなる。

朝のみ・夜のみが記録された日は、存在する点だけを打つ。

## 記録一覧

日付降順。1 日 1 行で、その日の朝・夜をまとめて表示する。

### 記録がある日

| 要素 | 内容 |
| --- | --- |
| 日付 | `9/5（金）` |
| 記録状況 | `朝・夜` / `朝のみ` / `夜のみ` |
| 体力 | `体力 3.5 → 1.5`（朝 → 夜） |
| 気力 | `気力 3.0 → 2.0`（朝 → 夜） |
| コメント | 抜粋を 1 行。あふれる場合は省略記号 |

列見出しを持たない文脈のため、差分は符号付き数値ではなく **`起点 → 現在` の矢印形式** を使う。片方しか記録がない日は矢印を出さず、存在する値のみを表示する。

行をタップすると [その日の記録](/docs/design/screens/record-detail) に遷移する。

### 未記録の日

記録が 1 件もない日は、破線の枠に `9/3（水）未記録` と `＋ 記録する` を並べた行として表示する。タップすると同じく `/records/$date` に遷移し、そのまま入力できる。

過去日の入力導線はこの行のみとする。専用の「日付を選んで記録」導線は設けない。

### ページング

| 項目 | 仕様 |
| --- | --- |
| 初期取得 | 20 件 |
| 追加取得 | 末尾到達で次の 20 件（`offset` を進める） |
| 未記録日の生成 | サーバーは記録のある日のみ返す。未記録日の行は、取得済み範囲の日付を埋める形でクライアント側が生成する |

## 空状態

| 状況 | 表示 |
| --- | --- |
| 記録が 1 件もない | グラフ・一覧の代わりに「まだ記録がありません」と今日タブへの導線 |
| 選択期間内に記録がない | グラフ領域のみ「この期間の記録がありません」。一覧はそのまま表示する |

## 使用 API

| 目的 | エンドポイント |
| --- | --- |
| グラフ用データ | `GET /api/records?from=<期間開始>&to=<today>&limit=100` |
| 一覧（初期） | `GET /api/records?limit=20` |
| 一覧（追加） | `GET /api/records?limit=20&offset=<n>` |

30 日 × 1 日 2 件 = 最大 60 件のため、グラフ用のクエリは `limit=100` で足りる。
