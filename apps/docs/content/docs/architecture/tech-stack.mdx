## インフラ・ホスティング

デプロイ先は 2 パターンを想定している。詳細は[システム全体図](/docs/architecture/system-overview)を参照。

### パターン A: Vercel（マネージド）

| 技術 | 採用理由 |
| --- | --- |
| Vercel | TanStack Start のホスティングに最適化。Git push で自動デプロイ |
| Supabase / Neon | マネージド PostgreSQL。Free Tier で個人開発に十分。自動バックアップ付き |

### パターン B: 自前サーバー

| 技術 | 採用理由 |
| --- | --- |
| VPS (Hetzner 等) | コスト管理しやすく、構成の自由度が高い |
| Docker / Docker Compose | アプリ・DB をコンテナで一括管理。再現性のある環境構築 |
| Caddy | 自動 TLS・リバースプロキシ。設定がシンプル |
| PostgreSQL (セルフホスト) | VPS 上で直接 or Docker で稼働。マネージド DB との併用も可 |

## 技術選定の方針

### 原則

1. **TypeScript 統一**: フロント・バックエンド・インフラ設定まで TypeScript で統一し、型安全性を最大化
2. **軽量・高速**: 個人開発かつ Free Tier 運用のため、バンドルサイズとランタイムコストを最小化
3. **エコシステム整合性**: TanStack ファミリー（Router / Start / Query）を中心に据え、ツール間の統合を活用
4. **運用コスト最小**: マネージドサービスを活用し、インフラ管理の負荷をゼロに近づける

### TanStack Start を選んだ理由

| 比較項目 | TanStack Start | Next.js | Remix |
| --- | --- | --- | --- |
| ルーティング型安全性 | ◎ (TanStack Router) | △ (型推論が弱い) | ○ |
| SSR + API 統合 | ○ (Hono マウント) | ◎ (API Routes) | ○ (loader/action) |
| バンドラ | Vite | Webpack / Turbopack | Vite |
| React 19 対応 | ○ | ○ | ○ |
| 学習コスト | △ (新しい) | ◎ (情報が豊富) | ○ |

→ **型安全なルーティング**と**Vite ベースの高速な開発体験**を最優先し、TanStack Start を採用。

### Hono を選んだ理由

| 比較項目 | Hono | Express | Fastify |
| --- | --- | --- | --- |
| TypeScript 対応 | ◎ (ネイティブ) | △ (型定義が別) | ○ |
| パフォーマンス | ◎ | △ | ◎ |
| バンドルサイズ | ◎ (軽量) | ○ | △ |
| Edge / Serverless | ◎ (マルチランタイム) | △ | △ |
| Middleware エコシステム | ○ | ◎ | ○ |

→ **軽量・型安全・Serverless 最適化**の観点で Hono を採用。TanStack Start の API ルートにマウントして使用。

詳細な意思決定は [ADR](/docs/decisions/001-monorepo-tool) に記録する。
